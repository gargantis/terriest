# terriest: agent instructions

This repo is **public**, and **unlicensed**: the owner keeps all rights (Q-1). Never add a LICENSE file or licence headers. `package.json` says `"license": "UNLICENSED"`, and the bundled packages' notices still ship, in `dist/THIRD-PARTY-LICENSES.txt` (§20). Never commit home paths, account or user names, email addresses, machine names, `workers.dev` addresses (C-45) or other identity details. `npm run public-scan` enforces the built-in patterns, and the owner's denylist only where `$TERRIEST_PRIVATE_TERMS` names it: a file outside the repo that never enters it. Its first line says which scan ran. With the variable unset, as on CI, it checks the built-in patterns alone, so a green gate hasn't checked the denylist's terms; set to a missing file, it fails.

## The gate is the definition of done

```sh
npm run check
```

That is lint, public-scan, typecheck, unit tests (`vendor/hermet`'s included), the build with its licence notices and dist audit, and end-to-end tests in Chromium, Firefox and WebKit against the built page. It must pass before `/merge-to-main` lands a branch, at each milestone's exit and before a deploy (Q-18's alternative, the owner's decision of 2026-11-20). A commit on a session branch needs `npm run check:commit` green (lint, public-scan, typecheck and the unit tests but the whole-match replays, which `npm test` and the gate run: the owner's decision of 2026-11-21) and every end-to-end spec it adds or changes run by path. A commit that changes the simulation, the bots, the timeline, the session, the protocol or `src/net` runs `npm test` too. Never weaken either to make a build pass: fix the code. The gate's wall time is logged in `docs/acceptance.md` at each milestone's exit (§16).

- REQUIREMENTS.md belongs to the owner. Change it only as the plan records, citing the Q- or C-number.
- The plan's L-numbers are REQUIREMENTS.md's lines at commit 6254a1d. Since then one line was added after L286, so from L287 on, today's file runs one line later.
- M2's design is kept as `research/m2/DESIGN.md`. M2's code's and its report's "design §…" cite it, and its §14 numbers its questions apart from the plan's. "bots-F1" and "bots-F4" in comments are findings of M2's review, which §16's fall-back mark and D-5's slip release record.
- M3's is `research/m3/DESIGN.md`, its questions M3-Q1 to M3-Q28; PLAN's M3 amendments win where the build differs. Which design a "design §…" cites goes by directory: M2's in `src/core/sim` and `src/core/bot`, but M3's where the citation names it and throughout `src/core/bot/setups.ts`, which M3 wrote, but for its "design §8.6, M2"; M3's in `src/core/timeline`, `src/core/session`, `src/core/protocol`, `src/net`, `src/ui` and the network test page. Elsewhere it's the design of the milestone that wrote the line: M2's for the goldens, the determinism and tuning pages and the tuning report; M3's for `dev:local`, the build inputs, the dev-relay audit, the correction measurement and its report, and the networked specs and runs. **Code boundaries** (most are D-38's lint, which `scripts/eslint/config.test.mjs` tests)
- `src/core/**` is pure: no DOM, timers, clocks, storage or network, and no global object. The caller passes time in (§6).
- `src/core/**` imports nothing outside `src/core` but `src/config.ts` (the lint's `core-imports`, from M3), so the simulation, the timeline and the session never import three or any drawing, page, network, storage or build module (L252).
- Only `src/render/**` imports three (D-26), and only from `three` and `three/addons/…`, never `three/src/…`, which would bundle a second copy (§15).
- `src/core/sim/**` and the bot brain in `src/core/bot/**`, their tests aside, use only exact operations (D-1, D-39), under hermet's `exact-ops` rule. There, `Math` appears only as `Math.<name>`: never destructured, aliased or passed on. And arrays only: `Map`, `Set`, `WeakMap` and `WeakSet`, with their `Readonly…` and `…Constructor` types, appear only as keys, since a Map or Set iterates in insertion order, which can follow arrival order (§7.3, D-38).
- Every setting is in `src/config.ts` and nowhere else (§7.4). `src/config.test.ts` reports a copy by its name anywhere in `src` and `dev`: a setting's own name, or one a port would give it (its `PORTED_NAMES`, such as `netSettings`' fields and roslambo's `SEND_BEHIND`). It reports one by its value too: in `src/core/sim`, `src/core/bot`, `src/core/timeline`, `src/core/session` and `src/core/protocol`, a number anywhere that isn't whole or 0.5; and in `src/core/sim` and `src/core/bot` alone, in a top-level constant, or an object literal one holds, any number but 0, or an equal array, as a port of the M0 spike's own constants would hold them. A code that only looks like a setting, such as a piece kind, says `not a setting` on its line. In `src/core/sim` and `src/core/bot` that's every top-level code the scan would flag: a bit, a phase, a kind, a version, a coefficient, a scene's coordinate, the brain's geometry, each as `// not a setting: <what it is>`. The scan can't see a whole number inside a function, so there the rule holds by review: read the setting from `SimParams`, `BotParams` or `netSettings()`, never a local copy. Run `npx vitest run src/config.test.ts` early.
- `src/config.test.ts` and `dev/tuning/model.test.ts` read PLAN's A.4 and A.5 and REQUIREMENTS' Configuration table at run time: the first table after each heading, a row per setting, its numbers in order, references such as D-8 aside, and "one", "twice" and "half" read as numbers. Keep the rows parseable, and when a row's wording or numbers change, change their maps with it: the config test's `CONFIGURATION`, `A4` and `A5`, and `dev/tuning/model.ts`'s `ROWS`. The config test's planted cases replace the first row in PLAN.md that starts `| Tumble guard |` or `| Idle friction | 8 `, so keep such rows to A.5.
- Only `src/net/trystero.ts` imports Trystero's code; types may be imported anywhere (D-18). Nothing but its own test imports that file statically: `NetGame.open` (`src/ui/game.ts`) loads its chunk with `import()` when a networked match opens, so a normal page, the determinism page and Practice never load Trystero (L238, the lint's `lazy-imports`). The lint holds M4's chunks to the same: the `#test=` pages, `src/frames.ts`, `src/determinism.ts` and `src/nettest.ts`, load only by `import()` from `src/main.ts`, for their fragments, and the bench's Worker, `src/bench/witness.ts`, is imported by nothing, its types included, `src/bench/virtual-room.ts` naming it only in its Worker's URL; each but by its own test (M4's design §1.53, §1.55). Its room config is `src/net/room-config.ts`'s, built with `vendor/hermet/room-config.ts`, a literal typed against `JoinRoomConfig`: an untyped spread made amorfus silently fall back to the library's own relays.
- `src/net/dev-relay.ts`, `npm run dev:local`'s relay, is loaded only with `import()` under `import.meta.env.DEV`, and `scripts/dev-relay-audit.mjs`, in the build's audit, fails a `dist/` with its chunk or a file naming it or `VITE_TERRIEST` (§15).
- Only `src/storage/**` touches browser storage.
- No root-absolute URL and no History API, so the site works from a subpath (L232). The fragment is set with `location.replace`.
- Every external host is listed in `third-party.json`; the dist audit fails on any other but the site's own address, terriest.com, which `index.html`'s link-preview tags name in the absolute URLs unfurlers need and the page never requests (`scripts/audit-dist.mjs`' `ignoredHosts`; `e2e/link-preview.spec.ts`).
- On terriest.com, Cloudflare's edge adds its Web Analytics beacon to the page, one `<script>` from static.cloudflareinsights.com before `</body>`, so the live page is `dist/index.html` with that tag added. `public/_headers`' script-src allows that host, by its host alone, and `third-party.json` lists it as kind `analytics` (C-58). The build never holds the beacon, so no spec sees it: `scripts/headers.test.mjs` pins the policy.
- `package.json` says `"sideEffects": false`, so the bundler drops a module none of whose exports the page uses: that keeps the goldens' scripts, which `src/core/sim/index.ts` reaches through `canaryHash`, out of the page's module (M2's design §7.5, from M4). So no module in `src` is imported for its side effects alone; what must run at start-up is called.
- The module paths of §6 are part of the contract: the lint, and from M2 the golden files, depend on them.

**The simulation and its goldens** (from M2)
- Golden hashes pin the simulation's bits in Node, every engine and arm64 (§16). Any change to the simulation or its settings changes them. Re-emit them on purpose, with `TERRIEST_EMIT_GOLDENS=1 npm run emit-goldens`, and say so in the commit. That's allowed until the first release.
- The emit is guarded twice (§15). The script refuses without `TERRIEST_EMIT_GOLDENS=1`, and runs `src/core/sim/golden.test.ts` with a second variable, `TERRIEST_EMIT_GOLDENS_BY_SCRIPT=1`, which only it sets. The test writes `goldens.json` only with both, and only once every run covers its spec, and with the first alone it fails. So never export either: run the script.
- `src/core/sim/step.test.ts`'s bit pins tie the port to the M0 spike's bits, under a configuration copy at M0's values written out there, so tuning never moves them. A mismatch is a port bug. Re-pin only for a deliberate rule change, named in the commit, as the slip release's was (D-5).
- The slipping flag's hold-off reads its own setting, `slipHoldOffMetres` (A.4's Slip-out row), not the re-arm gap, so the two tune apart (D-5). The push assist takes the restitution threshold as the speed above which the ball is moving, so tuning the threshold moves both (C-18).
- `step` advances its state in place, and depends only on that state and its inputs: nothing in a `Sim` carries from one call to the next, so one `Sim` steps any states of its pack size (§7.2). Keep every scratch entry written before it's read.

**Drawing**
- Drawing reads every animation but barking from the state, with how far through it is (L345). It keeps only blends, smoothing offsets, the timings it is fading out and each bark's start, so a rollback or a resync redraws it right (D-27); and, from M4, four things no animation's timing depends on: the camera rig's yaw, each viewer's own; the ball's drawn roll and the dust's puffs; each latched goal's latch time, which fades its celebration in; and the drawing clock's paused time, which stops the fades with Practice's pause (M4-Q35, `src/render/view.ts`). It never feeds anything back to the simulation.
- Coats and bandanas go by list index. The state, storage and messages carry a coat's index in the coat list and a terrier's pack, never a colour, and drawing looks up the colours and patterns (§12, D-27). The number of coats is in `src/config.ts`, so the build hash covers it (D-21).
- The stand-in skinned model stays out of `dist/`. From M4 the tests generate it with `scripts/make-standin.mjs`, or keep it in `e2e/fixtures/`, and serve it to the built page by request interception (D-27, C-33). The dist audit fails a `.glb` in `dist/` anyway.

**The boot page** (D-30)
- `index.html` holds the loading message and its `noscript`, shown until the app has started, so the page is never blank. `public/boot.js`, a classic script, runs its checks before the module and holds every failure message's text.
- `html[data-boot]` reads a failure's code at once where boot.js's own checks fail: `F` (opened from `file://`) or `S` (an insecure context). Otherwise it reads `loading`, then `started`, `W` (no WebGL 2, which the module reports when it makes the page's one context) or `L` (not started within 20 s). The specs read it (`e2e/lib/page.ts`).
- `window.terriestBoot`, with `started()` and `noWebGL2()`, exists only once `F` and `S` have passed, so where they fail the module does nothing. The module calls `started()` once its first screen shows, Home (from M4's phase 2 also Join's "Connecting…" or the other-tab message), which takes the message down, and only then starts the stage's compile behind that screen, so the 20 s timeout never counts the compile (M4-Q38, `src/ui/app.ts`).
- The page has one main landmark at a time: the message's, then the app's, `<main id="app">`, which `src/main.ts` makes on the normal page only, holding the stage's box `#stage` and the screen's `#screen`, and which stays hidden until `started` (M4-Q1, `index.html`). The stage's canvas, an image named "The pitch", shows only on Pre-match and Match (M4-Q9). A `#test=` page makes its own landmark and never `#app`.

**Tests**
- New behaviour needs a test through the real page and its controls (L344). A harness that bypasses the real page proves nothing about the product: amorfus's two worst first-build defects passed a green gate that way.
- The `#test=` pages (determinism, net, frames, from M2 to M4) and `window.terriestTest` never change what a normal page does. A spec sets `window.terriestTest = {}` before load (`installHook`, in `e2e/lib/page.ts`); once started, the page adds `inspect()` and `hashAt(t)` to it. `inspect()` returns `src/ui/inspect.ts`'s `Inspection`, which `src/main.ts` re-exports: the screen and a message's code, the menu, the renderer's figures, what a spectator's camera follows among them (`render.camera.follow`), the match held with its timer's figures, its room's peers and the refusal its status reports, and its timeline's clock jumps, its announcements, which outlive its screens, a pitch screen's controls, view and layers, the frame loop's and the start-up's times; `hashAt(t)` the held timeline's final hash at t. `#test=frames`, the bench (`src/frames.ts`), likewise adds `bench`, its `status()` and `report()`, only to a spec's hook, once its match is open, as `#test=net` adds `net`. Three fields a spec may set change what the page loads or contacts, each by the plan's leave: `modelUrl` (D-27), and `relay` and `ice`, a loopback relay alone (M4-Q3, from M4's phase 2). Specs seed A.3's storage before load (`seedStorage`), each key only while it's absent, as a player's stored choices: the gate's low quality and a fixed player ID (M4-Q4). A normal page never has the object.
- `#test=determinism` (`src/determinism.ts`, a chunk of its own that only that fragment loads) replays every golden run and the canary in the built bundle and compares them with `goldens.json`. It makes no WebGL context, calls `started()` once its landmark shows, and publishes `window.terriestDeterminism`, a `DeterminismReport`, and `html[data-determinism]`, `pass` or `fail`, which `e2e/determinism.spec.ts` reads. That global is the page's own: a normal page never has it, and `window.terriestTest` stays the normal page's hook.
- `#test=net` (`src/nettest.ts`, a chunk of its own with no WebGL context; its parameters and hook's types in `src/nettest-params.ts`) plays a match without the screens, over Trystero and the one relay it's given, or Practice's local transport, with a status for a person to read. Only with a spec's `window.terriestTest`, and only once its match is open, it adds `net` to it: `report()` and `hashAt(t)`. A page that refuses its parameters says so and contacts nothing, with no Trystero and no hook. A production build takes only `third-party.json`'s relays or a `ws:` one on the loopback; a dev build any, and `npm run dev:local`'s when none is given (M3's design §6.7).
- Shared test support, which never ships, sits beside the code, and only tests import it, but for the dev tuning page and its metrics, which take `src/core/sim`'s `testing.ts` and `cases.ts`: `src/core/sim/testing.ts` (with `cases.ts`, `match-testing.ts`), `src/core/timeline/testing.ts` (`Pump`, `NetPump`, `Watch`, `twin`, `expectAgreement`, and `inside`, a timeline's insides, with `removed`, the voters its lineage removed for silence while connected), `src/net/setups-testing.ts` (R-7's replay, and from M4 the screens match's setup on the specs' keys and the Ready band's sweep, its latitudes the spec reads from it), `src/net/freezes-testing.ts` (`Rig`, with `page`, `partition`, `settle` and `expectOneMatch`, and `freezes`, `cutOff`, `partitioned` and `joinerHeld`), `src/net/practice-spec-testing.ts` (M4's Practice specs' scripts played whole over Practice's own timeline), `src/ui/world-testing.ts` (`World`), `src/ui/clock-testing.ts` (`FakeClock`, `fakePage`), `src/ui/dom-testing.ts` (a DOM for Node, enough for the screens, with `cssDeclarations` and `cssLength` to read what a stylesheet asks of a box, `cssLength` taking `calc()` and `env()`'s fallbacks), `src/ui/pitch-testing.ts` (the pitch screen's fakes: the stage, the view, the controls, a `Match` over a set state, the stores), `src/ui/app-testing.ts` (`appRig`, an App on the DOM fake with a fake for each part the page hands it, `realGuard` for the page's own leave guard, `drawer` for a real terrier drawer on each stage, a real `WakeLock` the browser refuses, `FAKE_MESSAGES` for every message code, and the transports `nowhere` and `refusing`), `src/ui/screens/readout-testing.ts` (`summaryOf`, `quantiles`, `FakeCopy`) and `src/audio/audio-testing.ts` (`FakeContext`, `FakeAudioWindow`, `FakeAudioDocument`); and for the end-to-end specs, `e2e/lib/browsers.ts`' `openAppPage`, a normal page of the built app in a browser a test launched, its storage seeded with `personId(7, k)` and low quality, the hook's relay the local one and its ICE local, 640 × 360, the pad's stub if asked, watched and started, and `waitForStart`; `e2e/lib/gamepad.ts`, the stubbed pad of the standard mapping that `e2e/pad-menus.spec.ts`, the Practice specs and the screens' match press; and `e2e/lib/touch.ts`, the CDP touches of `e2e/touch.spec.ts`, several fingers down at once. Build on them rather than writing another pump.
- vitest runs test files in parallel and a file's tests one after another, and whole matches are most of the unit stage's CPU (§16): the bot marks', and from M3 the network simulator's. So a long loop goes in a file of its own, none much over 8 s alone, as each mark, the regulation mark's four files, the two tunnelling files, M3's split network files (`bots-setups-1` to `-6` and the like), M4's Practice setups (`practice-spec-whole-1` to `-6` and `practice-spec-goal-1` to `-4`) and the screens match's (`screens-setup-1` to `-13` and `screens-hold-start`) do. Never cut a mark's or a network test's seeds, or a scene, to save time. These whole-match replays (every test in `src/net` but its unit files, the bot marks, `src/ui`'s freeze matches and the timeline's whole-match file) are listed in `vitest.quick.config.ts`, which `check:commit` runs without them: a new whole-match file goes in one of those places or is added there, and a new unit file in `src/net` goes in its `NET_UNIT`.
- Firefox draws WebGL only with a display, so the gate runs under WSLg or `xvfb-run` (C-6). Every spec checks WebGL 2 in its engine first (`expectWebGL2`), the boot failures' included, so a run without a display fails there at once, not on a timeout. `GALLIUM_DRIVER` opts in to the GPU path, and then every Chromium the gate launches takes ANGLE's GL flags (`e2e/lib/gl.ts`); unset, no engine gets a GL flag.
- Nothing in a test depends on the frame rate. The gate draws in software, at 5–26 frames a second for a busy scene, and the timeline and the gamepad run on timers (C-6, D-29, D-31). The gate plays its matches at the low render quality, a real player setting (C-6, D-33).
- A spec whose tests launch their own browsers (from M3, through `e2e/lib/browsers.ts`: all three engines for a match, or Chromium's contexts alone, as `e2e/watchers.net.spec.ts` and `e2e/duplicate.net.spec.ts` take) is named `*.net.spec.ts`. It then runs once, in the `net` project; every other spec runs once in each engine (`playwright.config.ts`). A test there may still launch a browser of its own engine for a launch switch, as `e2e/boot.spec.ts` does to turn WebGL 2 off.
- The e2e guard allows only the servers a spec loads from and the local relay it names. Every spec imports `test` from `e2e/lib/guards.ts`, the `*.net.spec.ts` and `.run.ts` files too: its automatic `guard` fails a test on a console error, a WebGL error included in every engine though Chromium and Firefox log those as warnings, or a request outside `guard.allowed`. A test that breaks a load on purpose may list the browser's own errors for it in `guard.allowedErrors`, each pattern matching an error's whole text, and never the page's own (§16). A page the fixture doesn't own, in a browser a test launches itself, gets `watchPage` and `expectEverywhere`: in a `*.net.spec.ts` or a `.run.ts` file, where the guard's own page goes unused, `openNetPage` (`e2e/lib/browsers.ts`) watches each page it opens, its base URL and relay allowed. Never allow a public host: the gate contacts none, `third-party.json`'s included (§16). Every spec that reloads or leaves a page accepts its leave prompt (`acceptLeavePrompt`), but `e2e/room.net.spec.ts`, which dismisses one on a connected player's page to check the page keeps its room (M4's design §5.11).
- A Playwright spec can't import at run time a module that imports JSON, such as `src/net/room-config.ts`, and so `src/nettest-params.ts`: Node takes JSON only with an import attribute. Type imports are fine.

- The owner's attended steps (the checks by hand, the tuning, the bots' level, the look) don't hold up a milestone. Settle one provisionally as §17 says, log it as owner-pending in `docs/acceptance.md`, and go on. Each lands before M5's deploy.

## Branches

Every session works on its own branch, and `main` moves only by fast-forward: `/merge-to-main` lands a branch, and `/sync-with-main` brings `main` into one that has fallen behind. Questions, including prompts that start with "I want", get answers rather than changes. The rules are in `.claude/rules/`: [session-branches.md](.claude/rules/session-branches.md) and [always.md](.claude/rules/always.md).
